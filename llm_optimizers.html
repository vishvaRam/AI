Why Vanilla Gradient Descent Fails in LLMs

Standard Stochastic Gradient Descent (SGD) treats all parameters identically. However, inside a Transformer model, some weights handle common words while others manage critical but rare tokens. If an optimizer uses a single blanket step size, it creates erratic training stalls. Modern models bypass this limitation via **Adaptive Optimizers**.

1st Moment: Momentum ($m_t$)

Acts like a heavy rolling ball. It tracks an exponentially decaying average of past gradients. If the model hits a sudden flat plateau on the error surface, momentum carries the parameter updates smoothly right through it.

2nd Moment: Scaling Vector ($v_t$)

Tracks the variance of the gradients by keeping a running log of squared updates. The optimizer divides the step size by $\sqrt{v_t}$, which automatically scales down fast-changing variables while boosting columns that receive rare updates.

Weight Decay Correction

Original Adam combined weight decay inside its moving averages, which accidentally warped scaling updates. **AdamW** separates decay entirely, scaling it out independently to keep attention weight values regularized and stable.

Where do Optimizers execute in LLMs?

The optimizer coordinates parameters outside the neural layer blocks. It is invoked at the very end of the training pass loop:

Step 1 Tensors complete a Forward pass and compute Cross-Entropy Loss.
Step 2 The Backward pass processes parameters via calculus chain rules, generating raw gradients.
Step 3 (Optimizer) **AdamW sweeps across the model parameters**, reads raw gradients, computes moving moment factors, subtracts independent weight decay, and updates attention projections.
Step 4 Gradients are wiped via optimizer.zero_grad() to prep for the next data batch.
