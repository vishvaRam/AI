The Math Behind AutoRound Optimization

Naive rounding to the nearest integer truncates delicate semantic states, introducing substantial quantization error at ultra-low widths (like INT4 boundaries). **AutoRound** treats quantization as an ongoing fine-tuning process. It groups layers into blocks and uses **Sign-SGD** to iteratively adjust rounding direction parameters, preserving the network's processing fidelity.

Continuous Rounding ($V$)

AutoRound bypasses hard integer truncation by mapping rounding states to a continuous tracking variable ($V$). Passing $V$ through a rectified bending function scales values smoothly between integers, matching structural gradient flows.

Sign-SGD Optimization

Instead of scaling updates by raw, erratic gradient sizes, AutoRound uses **Sign-SGD**. It extracts only the directional *sign* ($\pm 1$) of the derivative, ensuring exceptionally smooth parameter adjustments across non-convex calibration spaces.

Block Reconstruction Loss

Optimization targets output discrepancy layers sequentially. Over a rapid 200-step phase, AutoRound forces the compressed weights matrix ($\hat{W}$) to mimic the native FP16 activation outputs ($Y = WX$), keeping loss near zero.

Execution Phase: Where does AutoRound fit?

AutoRound runs as an offline **Post-Training Quantization (PTQ)** optimization pass, executing directly after full precision model weights are compiled:

Step 1 Load uncompressed base model parameters in full precision (FP16 or BF16) along with a clean validation calibration data batch.
Step 2 (AutoRound) The weights are split block-by-block. Sign-SGD jointly updates the continuous rounding parameter grid ($V$) over a fast 200-step optimization window.
Step 3 The tuned continuous coordinates drop into absolute quantized integers, yielding an optimized low-bit model ready for high-throughput vLLM serving.
