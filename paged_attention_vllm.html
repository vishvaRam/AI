Overcoming KV-Cache Memory Fragmentation

Logical Tokens Block

As an LLM streams text tokens sequentially, their calculated Key-Value vectors form continuous logical tracking strings. The model groups these into virtual logical blocks of fixed sizes (e.g., 4 tokens per block).

The Block Page Table

Acts exactly like an operating system's MMU. The Page Table acts as a translational map layer, linking continuous, sequential logical token keys to scattered, non-contiguous spots inside physical VRAM.

Physical Cache Pool

By chopping VRAM into a uniform grid of physical block addresses, vLLM appends newly generated tokens to any available page, eliminating up to 96% of standard memory allocation waste.

Traditional Allocation vs. vLLM PagedAttention

Static Allocation (HuggingFace Transformers Baseline)

Pre-allocates contiguous tracks matching maximum context parameters ($N_{\text{max}} = 2048$). If an extraction payload terminates early at index 120, the remaining contiguous space from indices 121 to 2048 remains completely locked, unsharable, and entirely wasted.

PagedAttention Strategy (vLLM Engine Architecture)

Memory is allocated piece-by-piece using small 16-token page chunks. If a generation path needs additional slots, vLLM dynamically maps a new, unallocated block address from anywhere in the physical grid pool. This dynamic approach **reduces memory overhead by up to 96%**, allowing servers to scale up active query batch loads safely.
